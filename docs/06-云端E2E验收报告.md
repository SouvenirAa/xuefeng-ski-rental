# 06-云端 E2E 验收报告

> 阶段 F：真实 CloudBase PostgreSQL DML 与端到端验收
> 验收日期：2026-09-08
> 环境：CloudBase 环境 `snowpeak-rental-d6fao36oc26a8db9`（ap-shanghai），PostgreSQL 实例 `cloudbase-pg`

## 1. 验收目标

在真实云数据库上，通过浏览器端到端走通三角色的登录、权限、CRUD 与维修单 RPC 生命周期，验证以下要点：

1. CloudBase Auth 的 `usernamePassword` 登录策略真实生效；
2. RLS 角色门禁（admin / staff / contractor）在真实 SQL 层正确拦截越权访问（403）；
3. 维修单写入链完全走 SECURITY DEFINER RPC（`create_repair_order` / `start_repair` / `complete_repair`），不绕过 SQL；
4. 设备状态在维修生命周期中正确联动（在库 → 维修中 → 在库）；
5. 驾驶舱 KPI 在真实云数据下正确聚合；
6. 响应式布局在 1280 / 1440 / 1920 三档无错位、控制台无报错；
7. E2E 产生的数据可被精确清理，数据库恢复到基线快照。

## 4. 维修单 RPC 生命周期（核心验收）

以设备 `SN0002`（item_id=2，Head XTC 滑雪板 #2）与承包商「峰顶装备维修」（contractor_id=1）为主线，完整走通一次维修生命周期：

1. **创建**（admin）：申请日期 2026-09-08，故障描述「E2E测试故障描述」→ `repair_id=11`，`status=维修中`，`SN0002` 由「在库」转「维修中」。
2. **开始**（contractor）：RO-0011 `status` 由「待维修」转「维修中」，页面提示「已开始维修」。
3. **完成**（contractor）：填写完成日期 2026-09-08、工时 0.5h、说明「E2E测试维修说明」→
   - `status=已完成`，`repair_date=2026-09-08`，`repair_hours=0.50`
   - `calculated_cost=100.00`（冻结费率 ¥200.00/小时 × 0.5h，服务端按申请日期冻结）
   - `SN0002` 由「维修中」恢复「在库」

> 关键验证点：费率冻结与成本计算全部在服务端 RPC 内完成（前端 cloud 模式不计算），且设备状态联动由同一事务保证。
