# 案例 01 · 雪峰滑雪租赁管理系统 — 系统与技术设计

> 版本定位：**第一版 = 单机教学演示系统**（DataService + localStorage），不接入云端。

---

## 1. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端框架 | React 18 + Vite + TypeScript | 组件化、类型安全 |
| 组件库 | TDesign React | 中文后台组件，适合教学演示 |
| 图表 | ECharts | 驾驶舱可视化 |
| 路由 | React Router | 页面路由与权限守卫（UI 层） |
| 状态 | React Context / 自定义 Hook | 登录态与全局数据 |
| 数据层 | DataService（内存 + localStorage 持久化） | 模拟表/约束/关联，保留迁移接口边界 |
| 构建 | Vite | 快速启动 |

> **关于"本地模拟 API"**：第一版采用一个轻量的 `DataService` 数据访问层，内部用内存数据 + localStorage 持久化模拟数据库（表、主外键、唯一约束、关联查询、聚合统计）。该层对外暴露与真实后端一致的接口（`list/create/update/remove` 及业务方法），后续可替换为 CloudBase + PostgreSQL 而不改动页面代码。**本方案不宣称支持真实多人协作、远程访问或并发控制。**

## 2. 系统架构

```text
┌─────────────────────────────────────────────┐
│  展示层  React 页面（TDesign 组件）          │
│  Login / Dashboard / 各业务列表与表单        │
│  （全局顶栏显示"教学演示环境"标识）           │
└──────────────────┬──────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────┐
│  应用层  Hooks / 服务（业务规则、权限判断）   │
│  （权限为服务层模拟，非安全边界）             │
└──────────────────┬──────────────────────────┘
                   │ 调用
┌──────────────────▼──────────────────────────┐
│  数据访问层  DataService（模拟表 + 约束）     │
│  list / create / update / remove / 聚合统计  │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  存储  localStorage（单机持久化演示数据）     │
└─────────────────────────────────────────────┘
        （迁移路径：DataService → CloudBase + PostgreSQL，见 §7）
```

分层原则：页面组件不直接操作数据，业务规则集中在服务层，数据访问集中在一个模块——便于课堂讲解"分层架构"与"关注点分离"。

## 5. 关键业务逻辑说明

1. **合同创建**：选择客户 → 添加设备明细（单品，`quantity=1`，自动带出日租金，校验同一合同不可重复加入同一物品）→ 计算总额 → 生成合同并记录借出时间与借出门店。
2. **换货/增减**：在合同详情执行"归还旧 + 增加新"——旧明细 `status→已更换`（记录归还时间/归还门店），新增一条新设备明细（`status→借出中`）；同时写入两条共享 `change_group_id` 的 `CONTRACT_CHANGE`（`change_type` 分别为 归还 / 增加），在变更组层面计算一次 `amount_delta =（新日租金 − 旧日租金）× 剩余租赁天数`（负数退款）；整笔换货在一个 DataService 业务方法中原子执行。
3. **归还**：记录 `return_time` 与 `return_store_id`，更新 `RENTAL_ITEM.current_store_id` 与状态；当合同所有明细均已归还后，合同转"已完成"、写入 `completed_at` 并重新固化最终应收总额；已完成合同不可重新打开。
4. **维修**：在库设备报修 → 员工创建维修单（按生效日期固化 `rate_id`；设备 `status` 在库→维修中，维修单 `status`=待维修）；被分配承包商"接单/开始维修"（维修单 `status` 待维修→维修中）；承包商填写完成日期/工时/备注（维修单 `status→已完成`，`calculated_cost = repair_hours × hourly_rate`，设备 `status→在库`）。状态单向、不可跳跃/回退，第一版不实现取消；借出中设备不可报修。
5. **驾驶舱 KPI（口径见 01 §10）**：
   - 当前设备利用率 = 借出中有效设备数 ÷ 有效设备总数（不含已报废；维修中计入总数、不计入借出）；
   - 本月营收 = 本月完成合同（按 `completed_at` 所在月份）的最终应收总额之和（含换货补差、扣退款）；
   - 平均维修周转时长 = 已完成单的 `repair_date − request_date`（自然日）；
   - 门店库存分布 = 按 `current_store_id` × 状态汇总。
6. **引用完整性（删除约束）**：DataService 在删除/修改前检查引用——客户被合同引用、门店被设备/排班/合同明细引用、员工被账号/合同/排班引用、承包商被账号/费率/维修单引用时拒绝删除；费率被维修单引用时拒绝修改/删除；被引用时返回明确失败原因供界面展示。

## 6. 模拟实现 vs 真实实现边界

| 功能点 | 第一版实现方式 | 达成等级 |
| --- | --- | --- |
| 表单校验（必填/范围/日期） | 真实实现（前端 + 服务层校验） | 真实 |
| 唯一约束（email/item_code/contract_no 等） | DataService 内存唯一检查 | 教学模拟（单机） |
| 外键与关联查询 | DataService 内存引用与 join 模拟 | 教学模拟 |
| 聚合统计（KPI） | DataService 对内存数据聚合 | 真实（数据来自种子数据） |
| 登录 | 账号表 + 占位密码校验 | 教学模拟 |
| 角色权限 | 服务层 `role` 判断 + 路由守卫 | 教学模拟（非安全边界） |
| 承包商"仅见本人单" | 服务层 `contractor_id` 过滤 | 教学模拟 |
| 原子业务方法（换货/归还） | 单线程同步执行，模拟事务 | 教学模拟（无并发） |
| 多人协作 / 跨设备共享 | 不支持（localStorage 单机） | 未实现 |

## 7. 迁移映射表（模拟 → CloudBase PostgreSQL）

> 依据 postgresql-development-cloudbase（v2.31.0）的 PG 落地规范整理，供后续升级参考。迁移时 DataService 接口签名保持不变，仅替换实现。

| 第一版（模拟） | 目标实现（CloudBase PG） |
| --- | --- |
| localStorage 存储 | CloudBase PostgreSQL，浏览器侧 `app.rdb().from('<表>')` 读写 |
| DataService 模拟表 | PG 表，经 `managePgDatabase(action=applyMigration)` 版本化迁移（`cloudbase/migrations/<14位时间戳>_<name>.sql`），DDL + `GRANT` + `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` + `CREATE POLICY` |
| 内存唯一检查 | 数据库 `UNIQUE` 约束（email / item_code / contract_no / UNIQUE(contract_id,item_id) / UNIQUE(contractor_id,effective_date) / UNIQUE(employee_id,work_date)） |
| 内存外键引用 | PG `FOREIGN KEY` 约束 |
| CHECK 范围校验 | PG `CHECK` 约束（金额非负、时间范围、状态枚举、quantity=1、工时步进） |
| 模拟登录 | CloudBase Auth 用户名密码登录：`auth.signInWithPassword({ username, password })`，会话判定用 `auth.getSession()`（**不用** `auth.getUser()`/`getLoginState()`） |
| 服务层角色判断 | 数据库 RLS 策略：`auth.role()` 判 anon/authenticated，`auth.uid()` 判当前用户；`ACCOUNT` 表作为业务角色来源（`uid` 与 `session.user.id` 一致），owner 列建议 `varchar(64)` 以匹配 `auth.uid()` 返回的 text |
| 承包商"仅见本人单" | RLS：`USING (contractor_id = (SELECT contractor_id FROM account WHERE uid = auth.uid()))` |
| 单线程"事务" | PG 事务（换货/归还的原子性由数据库保证） |
| 无并发控制 | PG 行级锁 / 事务隔离 |

**迁移关键注意点（来自 PG skill）**：owner/外键列用 `snake_case`；`auth.uid()` 返回 `text`（非 uuid），身份列建议 `varchar(64)`；不要在 RLS 策略里用 `current_user`；启用 RLS 前必须已建好 SELECT/INSERT/UPDATE/DELETE 策略，否则浏览器读写被默认拒绝。

## 8. 第一版明确不实现（迁移后目标）

- 真实身份认证与安全权限（RLS）
- 多人协作、跨设备共享与并发控制
- 云端文件存储（PG storage / pgstore bucket）
- 真实支付回调与退款
