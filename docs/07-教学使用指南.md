# 07-教学使用指南

> 面向授课教师：如何在课堂中使用「雪峰滑雪租赁管理系统」演示系统分析与设计全流程。

## 1. 教学定位

本案例覆盖一个完整信息系统从需求到上线的生命周期，适合：

- 本科《系统分析与设计》：需求分析 → ER/关系模型 → 权限矩阵 → 系统架构 → 实现与验收；
- MBA《管理信息系统》：业务流程数字化、角色权限治理、云端架构与数据安全。

案例全部人物、门店、合同数据为虚构内容，避免版权与真实企业信息问题。

## 2. 两种演示模式

| 模式 | 数据存储 | 登录 | 适用场景 |
| --- | --- | --- | --- |
| local | 浏览器 localStorage | 模拟校验（demo1234） | 无网络课堂、单机演示、快速上手 |
| cloud | CloudBase PostgreSQL | CloudBase Auth（真实） | 展示行级安全、多人协作、真实部署 |

- local 模式：`cd app && npm install && npm run dev`，访问 http://localhost:5173
- cloud 模式：配置 `.env.local`（见 `app/.env.example`）后启动；线上环境见 README「线上访问」

## 3. 角色与权限演示要点

| 账号 | 角色 | 关键演示 |
| --- | --- | --- |
| admin | 管理员 | 全部模块增删改查、创建维修单 |
| staff | 店员 | 客户/合同/维修操作；设备只读 |
| contractor | 承包商 | 仅看到并处理自己的维修单 |

**越权演示**（cloud 模式）：用 staff 账号访问「门店管理」、用 contractor 账号访问「驾驶舱」，会命中 RLS 拒绝并跳转 403 页——这正是行级安全边界最直观的课堂演示。

## 4. 核心业务场景

### 4.1 租赁全流程

创建合同（价格快照）→ 换货（差价补退）→ 部分/批量/跨店归还 → 合同自动完成。

### 4.2 维修全流程

创建维修单（冻结费率 + 设备转维修中）→ 承包商开始维修 → 完成维修（按冻结费率算成本 + 设备恢复在库）。

### 4.3 驾驶舱

设备利用率、本月营收、平均维修周转、门店库存分布——展示「数据 → 指标 → 决策」的闭环。

## 5. 验收方式

- 自动化：`npm run typecheck / lint / build` 与 16 个 `validate:*`、`audit:migrations` 全绿；
- 端到端：见 [云端 E2E 验收报告](06-云端E2E验收报告.md)，含三角色登录、越权 403、RPC 写入链与响应式截图。

## 6. 课堂建议节奏

1. **需求阶段**：对照 [需求分析](01-需求分析.md) 讲解业务规则（费率冻结、换货差价、跨店归还）；
2. **设计阶段**：对照 [数据设计](02-数据设计.md) 与 [系统设计](03-系统设计.md) 讲解 ER 模型、RLS 策略与 SECURITY DEFINER RPC；
3. **实现阶段**：现场运行系统，演示业务流程与角色权限；
4. **验收阶段**：展示自动化测试与云端 E2E 报告，说明 fail-closed 与行级安全的设计取舍。
