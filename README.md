# 雪峰滑雪租赁管理系统

> 本科《系统分析与设计》与 MBA《管理信息系统》课程教学案例  
> 当前版本：完整教学演示系统（本地 + CloudBase PostgreSQL 双模式，已部署上线）

## 项目简介

本项目将滑雪租赁企业案例中的业务需求、数据表和业务规则，转化为一个可以实际运行的网页管理系统，用于演示从需求分析、数据设计、系统设计到 AI 辅助实现、云端迁移与端到端验收的完整过程。

项目采用“双模型智能体协作”方式开发：**WorkBuddy（DeepSeek V4 Pro）**负责读取项目、实现与验收，**GPT** 负责阶段拆解、提示词生成和独立审核。审核模型可替换为通义千问、Kimi、GLM、DeepSeek、豆包等具备代码审查和任务规划能力的智能体。系统采用 React 18 + TypeScript + Vite + TDesign + ECharts 技术栈，支持两种数据模式，由环境变量 `VITE_DATA_MODE` 控制：

- **local 模式**：无需服务器，业务数据保存在浏览器 `localStorage`，便于课堂演示与快速上手；
- **cloud 模式**：接入腾讯云 CloudBase（Auth 登录 + PostgreSQL 数据库 + 静态托管），具备真实登录、行级安全（RLS）与多人协作能力。

所有人物、门店、合同及业务数据均为虚构内容，仅用于课堂教学。

## 已实现的业务流程

### 租赁流程

1. 店员或管理员选择客户与在库设备创建合同。
2. 合同保存时固化设备日租金快照并将设备改为“借出中”。
3. 租赁期间可进行换货，系统按剩余天数和合同价格快照计算补收或退款。
4. 支持部分归还、批量归还和跨门店归还。
5. 所有有效明细归还后，合同自动转为“已完成”。

### 维修流程

1. 管理员或店员为在库设备创建维修单。
2. 系统按申请日期冻结承包商当时的小时费率，并将设备改为“维修中”。
3. 被分配的承包商只能查看和处理自己的维修单。
4. 维修完成时按冻结费率与维修工时计算成本，设备恢复为“在库”。

## 角色与演示账号

| 账号 | 角色 | 主要权限 |
| --- | --- | --- |
| `admin` | 管理员 | 基础资料、人力、合同、维修单和系统管理 |
| `staff` | 店员 | 客户、合同和维修单操作；设备只读 |
| `contractor` | 承包商 | 只查看并处理分配给自己的维修单 |

密码分两种模式：

- **local 模式**：三角色密码均为 `demo1234`（教学占位，仅用于本地演示）。
- **cloud 模式**：密码在 CloudBase「身份认证」控制台按账号单独设置（须满足 ≥8 位规则），不写入仓库。

## 可演示操作

下面的操作可直接用于课堂演示、课程答辩或系统验收。建议先用 **local 模式**熟悉业务，再用 **cloud 模式**展示真实认证、数据库权限和多人共享效果。

### 1. 登录、角色与越权拦截

1. 分别使用 `admin`、`staff`、`contractor` 登录，观察三种角色的首页和左侧菜单差异。
2. 登录后刷新浏览器，验证会话恢复；点击右上角用户菜单退出，验证受保护页面重新跳转到登录页。
3. 使用 staff 直接访问 `/stores` 或 `/employees`，使用 contractor 访问 `/dashboard`、`/customers` 或 `/contracts`，观察 403 页面。
4. 在 cloud 模式中说明：菜单隐藏只是用户体验，真正的权限边界还包括 Hook 前置门禁、PostgreSQL RLS、列级 ACL 与 RPC 函数体鉴权。

### 2. 基础资料管理

使用 admin 可演示：

- **客户管理**：按姓名、电话或邮箱搜索；新增客户；编辑身高、体重、鞋码等资料；删除未被业务引用的客户。
- **设备管理**：按编号、名称、类别、门店和状态筛选；新增/编辑设备；观察“一件设备一条记录”和“归属门店/当前门店”两个字段。
- **门店管理**：新增、编辑和删除门店；查看每个门店的当前设备数量。
- **承包商与费率**：维护承包商资料；增加按日期生效的小时费率；查看历史费率和当前有效费率；观察已被维修单引用的费率不可修改或删除。
- **员工与排班**：维护员工资料；切换到周排班视图；新增、编辑或删除 08:00–22:00 范围内的班次；观察同一员工同一天仅允许一个班次。

使用 staff 可对比演示设备只读、门店/员工/承包商模块不可访问等权限差异。

### 3. 租赁合同完整闭环

建议使用 admin 或 staff，按以下顺序操作：

1. 进入「租赁合同」并点击「新建合同」，选择客户、经办员工、租出门店和一台或多台“在库”设备。
2. 提交后打开合同详情，确认设备状态变为“借出中”，合同明细保存创建时的日租金快照。
3. 对其中一条借出明细执行「换货」，选择替换设备和归还门店，观察系统按剩余天数计算补收或退款，并在时间线生成成组的“归还 + 增加”记录。
4. 对部分设备执行单件归还，观察合同保持进行中；再执行批量归还，观察全部有效明细归还后合同自动完成。
5. 选择不同归还门店，演示跨店归还：资产归属门店不变，当前位置更新为实际归还门店。

### 4. 维修单与承包商协作闭环

该流程适合展示多角色协作和数据库 RPC：

1. admin 或 staff 从“在库”设备创建维修单并选择承包商；系统冻结申请日期对应的小时费率，设备转为“维修中”。
2. 退出后使用 contractor 登录，只能看到分配给该承包商的维修单。
3. 点击「开始维修」，状态由“待维修”变为“维修中”。
4. 点击「完成维修」，填写大于 0 且为 0.25 小时倍数的工时；系统按冻结费率计算成本，并将设备恢复为“在库”。
5. 回到 admin/staff 页面查看完整维修记录，说明费用计算和设备状态联动均由数据库受控函数原子完成。

### 5. 驾驶舱与数据决策

- 查看设备利用率、本月营收、平均维修周转天数和已完成维修单数量。
- 查看门店库存分布图，比较不同门店的在库、借出和维修设备。
- 可在完成一份合同或维修单前后对比 KPI，展示“业务操作 → 数据变化 → 管理指标”的闭环。

### 6. local/cloud 双模式与数据安全

- **local 演示**：完成若干增删改后刷新，验证数据保留；在右上角用户菜单点击「重置演示数据」，恢复内置种子。
- **cloud 演示**：在一台电脑修改数据，另一浏览器刷新后可见，说明数据来自共享 PostgreSQL，而不是当前浏览器的 localStorage。
- **配置门禁**：将 cloud 模式的必要环境变量留空或把 `VITE_DATA_MODE` 写成非法值，应用会显示配置错误页，不会静默退回 local 假数据。
- **安全提示**：真实云端演示前建议建立专用教学账号和可清理数据；密码、Access Key、Token、`.env.local` 均不得提交到 Git。

### 7. 推荐的 15 分钟课堂演示顺序

| 时间 | 演示内容 | 教学重点 |
| --- | --- | --- |
| 0–2 分钟 | local/cloud 模式与三角色登录 | 同一 UI、不同数据源；身份决定能力 |
| 2–5 分钟 | admin 新增客户、设备并查看门店库存 | 基础 CRUD、外键、状态和位置建模 |
| 5–9 分钟 | 创建合同、换货、部分/批量归还 | 价格快照、换货审计、跨店归还、状态机 |
| 9–12 分钟 | admin 创建维修单，contractor 开始并完成 | 费率冻结、本人权限、RPC 原子事务 |
| 12–14 分钟 | 驾驶舱 KPI 与门店分布 | 从业务数据到管理决策 |
| 14–15 分钟 | 越权 403、RLS/ACL、测试与 Git 证据 | AI 生成代码仍需安全边界和独立验收 |

## 技术栈

- React 18 + TypeScript + Vite 5
- TDesign React / TDesign Icons
- React Router 6
- ECharts + echarts-for-react

## 快速运行

### 环境要求

- Node.js 18 或更高版本
- npm

### 本地模式（默认，无需服务器）

```bash
cd app
npm install
npm run dev
```

浏览器访问：<http://localhost:5173>

### 云端模式（接入 CloudBase）

1. 在 `app` 目录下创建 `.env.local`（模板见 `.env.example`），填入：
   - `VITE_CLOUDBASE_ENV_ID`：CloudBase 环境 ID
   - `VITE_CLOUDBASE_REGION`：地域（如 `ap-shanghai`）
   - `VITE_CLOUDBASE_ACCESS_KEY`：匿名访问令牌
   - `VITE_DATA_MODE=cloud`
2. 确保云端 PostgreSQL 已按 `cloudbase/migrations/` 应用迁移（4 个 migration）。
3. 启动开发服务器：

```bash
cd app
npm run dev
```

### 生产构建与预览

```bash
cd app
npm run build
npm run preview
```

## 数据说明

- **local 模式**：演示数据写入浏览器 `localStorage`，刷新后保留，可从右上角用户菜单「重置演示数据」恢复种子；
- **cloud 模式**：数据写入 CloudBase PostgreSQL，由 RLS 行级安全策略约束角色访问，跨浏览器、跨电脑、多人共享；
- 检测到本地数据损坏时，系统会进入数据恢复页面。

## 当前版本边界

当前仓库用于展示教学案例的完整成果，仍非可直接上线的生产系统：

- **local 模式**：登录与权限为前端模拟，不构成真实安全边界；
- **cloud 模式**：登录与行级安全由 CloudBase Auth + PostgreSQL RLS 提供真实边界，但演示账号密码由课程管理员管理；
- 匿名访问令牌（accessKey）仅用于教学演示环境的只读/受限访问，不应承载生产敏感数据。

## 教学扩展建议

1. 将滑雪租赁替换为实验室器材、图书借阅或车辆租赁，复用角色、状态机和双模型开发流程；
2. 新增“设备报废审批”或“合同逾期计费”，要求同时修改需求、Schema、RLS/RPC、页面和反向测试；
3. 比较 GPT、通义千问、Kimi、GLM、DeepSeek、豆包等模型在同一阶段提示词下的执行与审核差异；
4. 如需生产化，可继续扩展自定义域名、CDN、操作审计日志、备份恢复与正式密钥管理。
